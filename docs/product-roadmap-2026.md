# 咕咕机长 · 产品发展方向与开发计划（2026）

> 版本：基于 v0.8.1 现状 | 日期：2026-07-23
> 输入：产品源码与架构审查、2025–2026 市场竞品调研

---

## 一、产品现状盘点

**咕咕机长是什么**：Tauri 2 桌面提醒工具，核心差异化是「飞行动画提醒」——提醒不是一条系统通知，而是一架飞机带着文案框从屏幕飞过。

**已有资产**：

| 维度 | 现状 |
|---|---|
| 任务模型 | 定时 / 倒计时 / 节假日 / 纪念日，支持农历、按周重复、颜色标签、分组 |
| 表现力 | 8 种飞行轨迹 × 6 种飞机 × 6 种尾焰 × 6 种文案框，12 种音色 + 自定义音频/图片 |
| 桌面能力 | 全局快捷键、托盘、迷你悬浮窗、系统通知、开机自启、三平台（macOS/Win/Linux） |
| 工程 | 模块化架构、200 测试用例、CI/CD 三平台发布、深链 `gugufly://` |
| 商业 | 免费开源（MIT），README 已预埋 v1.0 Pro 计划（云同步/AI/主题市场/家庭共享） |

**已知短板**（来自 project-review.md）：安全性边界（XSS/CSP/命令注入）、两套更新机制并存、`main.js` 上帝模块、缺少上下文感知能力。

## 二、市场与竞品分析

### 2.1 赛道地图

咕咕机长站在三条赛道的交叉口，这是它最大的战略资产：

```
                 效率提醒（功能价值）
              Todoist / Due / 系统日历
                       │
        休息健康 ──────┼────── 桌面伴侣（情绪价值）
   Stretchly/Time Out/ │      Bongocat / Codex Pet /
      LookAway         │      华为闪光桌面 / QQ宠物
                       │
                    ★ 咕咕机长
              （动画信使：功能 × 情绪的混血）
```

### 2.2 关键竞品结论

**A. 休息提醒赛道（功能侧）** — Stretchly / Time Out / LookAway

- 2026 年这个赛道的决胜点已经不是"定时弹窗"，而是**智能时机（Smart Pause）**：检测会议、录屏、全屏视频、游戏、打字中，自动推迟提醒。LookAway（$19 买断）靠这一点 + 姿态/眨眼提醒 + Screen Score 统计做到品类标杆。
- 教训：提醒工具的死因不是功能不够，是**「三天后被用户关掉」**——在错误的时间打断用户一次，信任就丢一分。
- **咕咕机长的飞行提醒比"全屏遮挡"温和、比"系统通知"显眼，位置恰好。** 但没有上下文感知，飞行在演示/会议中飞过一次就是事故。

**B. 桌面伴侣赛道（情绪侧）** — Codex 桌宠 / Bongocat / 华为闪光桌面

- 2026 年桌宠全面爆发：OpenAI Codex 桌宠上线即出圈（宠物实时反映 Agent 状态：思考挠头、完成提醒、失败卖萌），社区一周内生成了 PetShare/PetDex 宠物图鉴站；Bongocat 仅靠换皮 + 记录点击冲上 Steam 热玩榜前十、峰值 19.45 万在线；华为「闪光桌面」主打"桌面情绪入口"获创新精品应用奖。
- 结论：**情绪价值 = 留存 = 传播**。人们爱的不是提醒，是"屏幕上有只属于自己的小东西在陪着我"。
- **咕咕机长的飞机天然是个"信使"角色**，但它目前是"用完即走"的动画，不是常驻伴侣。只差一步：让咕咕机长常驻桌面、有状态、有性格。

**C. 任务管理赛道** — Todoist / SingularityApp 等

- 不值得正面进入。咕咕机长不做"管理"，做"触达"。管理交给专业工具，我们通过 URL Scheme / 日历导入 / MCP 接收它们的输出即可。

### 2.3 核心判断

1. **功能赛道打不赢资源战，情绪赛道我们已有入场券。** 飞机上屏的那一刻是咕咕机长独有的"哇塞时刻"，任何竞品抄走都需要重做渲染层。
2. **2026 年的两个确定性趋势**：① 上下文感知（在对的时间出现）；② Agent 状态可视化（Codex 桌宠证明：用户需要"余光可见的后台状态"）。咕咕机长都能吃到。
3. **最危险的敌人是"被用户卸载"**，不是某个竞品。所有规划的第一优先级是提升 7 日/30 日留存。

## 三、发展方向（北极星）

> **愿景：从「定时放飞机的工具」进化为「你的桌面航空站」**
> 咕咕机长是常驻桌面的信使：在对的时间，用最好看的方式，把重要的事送到你眼前。

三个战略方向，按优先级：

### 方向 1：聪明 —— 在对的时间出现（上下文感知）
让每一次飞行都"恰逢其时"，这是留存的地基。

### 方向 2：陪伴 —— 从动画到角色（常驻信使）
迷你窗升级为有状态、有性格、可互动的"咕咕机长"本体，吃桌面伴侣趋势的红利。

### 方向 3：连接 —— 成为提醒的"显示器"（生态入口）
不做任务管理，做万物提醒的展示层：日历、AI Agent、快捷指令、MCP，任何来源都能让飞机起飞。

## 四、分阶段开发计划

> 原则：核心永远免费开源；Pro 只做"省事 + 增值"（同步 / AI / 云端素材）。
> 每个功能标注：[价值] 用户价值 · [竞争] 差异化 · [实用] 落地难度（★越多越难）

### 🚀 第一阶段 v0.9「聪明」（6–8 周）—— 先解决留存

| # | 功能 | 说明 | 价值 | 竞争 | 难度 |
|---|---|---|---|---|---|
| 1 | **智能时机（Smart Pause）** | 检测全屏应用 / 会议（相机+麦克风占用）/ 屏幕录制 / 勿扰模式时，自动推迟飞行并在恢复后补飞；用户可按任务设置"重要任务例外" | ★★★ | 对标 LookAway 核心卖点，休息提醒品类用户的第一诉求 | ★★★ |
| 2 | **专注模式（番茄钟 2.0）** | 倒计时升级为完整番茄循环：专注→小歇→长休，飞机作为阶段切换的仪式感；专注期间其他低优先级任务自动静默 | ★★★ | 复用现有倒计时基建，增量小 | ★★ |
| 3 | **自然间隔检测** | 键鼠静默 30s+ 才触发非紧急飞行（Stretchly 的 natural breaks 机制），避免打断心流 | ★★ | | ★★ |
| 4 | **工作时段 & 免打扰窗口** | 每天/每周可配置允许飞行的时间窗；窗口外任务自动顺延 | ★★ | | ★ |
| 5 | **工程债清偿** | 按 project-review.md：统一更新机制、修 XSS/CSP、`run_script` 参数化、`main.js` 拆分 | — | 安全性是上架商店的门票 | ★★ |

> 阶段目标：30 日留存翻倍。衡量：人均每周主动禁用次数下降、"紧急降落"使用频率下降。

### 🐤 第二阶段 v1.0「陪伴」（8–10 周）—— 建立情感连接

| # | 功能 | 说明 | 价值 | 竞争 | 难度 |
|---|---|---|---|---|---|
| 1 | **常驻咕咕机长（迷你窗 3.0）** | 迷你悬浮窗升级为角色本体：待机动画（打盹/扇翅）、有任务临近时躁动、飞行前"滑跑"起飞、完成后降落汇报；可拖拽、可点击快速交互（完成/推迟/静音） | ★★★ | 直接对标 Codex 桌宠/闪光桌面，我们有"会飞的信使"独属设定 | ★★★ |
| 2 | **状态机与性格系统** | 机长有心情/精力：按时完成提醒的事→开心 streak；连续忽略→委屈。文案库按心情变化 | ★★ | 游戏化留存（Bongocat/多邻国验证过） | ★★ |
| 3 | **WebDAV 云同步**（Pro） | 任务/设置/统计多设备同步，通用协议不绑定 vendor | ★★★ | README 已承诺，付费点 #1 | ★★★ |
| 4 | **皮肤市场 1.0** | 飞机/尾焰/文案框打包成"皮肤包"（JSON + 资源），支持导入导出与社区分享链接；官方出 3–5 套节日限定 | ★★ | PetShare 模式验证过 UGC 传播力 | ★★ |
| 5 | **成就与 streak 体系** | 基于现有飞行统计扩展：连续准时 N 天、首次农历节日、深夜拒飞等徽章 | ★ | | ★ |

> 阶段目标：7 日留存 ≥ 45%；皮肤包分享带来第一波自传播。

### 🌐 第三阶段 v1.1–1.2「连接」（8–12 周）—— 变成平台

| # | 功能 | 说明 | 价值 | 竞争 | 难度 |
|---|---|---|---|---|---|
| 1 | **日历导入（只读）** | 订阅系统日历/ICS 链接，会议自动生成"即将起飞"任务，带会议名飞行 | ★★★ | 会议提醒是桌面提醒最高频场景 | ★★★ |
| 2 | **MCP Server + Agent 联动** | 暴露 `gugufly` MCP 工具（add_task / fly_now / get_status），让 Claude Code、Codex、WorkBuddy 等 AI Agent 可以让飞机起飞——"构建完成""部署失败"用飞机送达；机长状态机映射 Agent 状态 | ★★★ | Codex 桌宠已验证需求，而我们是通用桌面层、不绑定任何 Agent | ★★ |
| 3 | **AI 自然语言建任务**（Pro） | "明天下午 3 点提醒我开会，每周五下午周报"→ 直接创建；本地小模型或用户自带 API Key | ★★ | Horo 验证过 NL 输入的爽感 | ★★ |
| 4 | **智能文案**（Pro） | AI 按任务类型/心情生成飞行文案（节日祝福、纪念日情话、会议毒舌提醒） | ★ | 情绪价值放大器 | ★ |
| 5 | **快捷指令 / Raycast / Alfred 扩展** | 各平台启动器一键起飞；补全 Windows 全局快捷键自定义 | ★★ | Stretchly 社区靠这个扩张 | ★ |
| 6 | **家庭/亲密共享清单**（Pro） | 共享纪念日 + "小信号"：给爱人的桌面飞一架带消息的小飞机（参考闪光桌面"亲密圈"） | ★★ | 差异化付费场景，情感传播极强 | ★★★★ |

> 阶段目标：Pro 订阅转化 ≥ 3% 月活；Agent/MCP 场景形成开发者口碑。

### 明确不做（战略克制）

- ❌ 完整任务管理（清单嵌套/看板/项目）—— 那是 Todoist 的战场
- ❌ 强制锁屏式休息提醒 —— 与"温和有趣"的品牌调性冲突
- ❌ 移动端 App —— 维护成本高，用"小信号"网页/小程序轻量触达即可
- ❌ 社交 Feed / 排行榜 —— 单机情感产品不需要社交压力

## 五、UI/UX 重设计方向

### 5.1 现状诊断

当前 UI 是"浅蓝卡片列表 + 下拉设置面板"，功能清晰但存在三个问题：

1. **隐喻缺失**：界面是"通用 Todo 列表"，没有用上自己最强的"飞行/航空"资产。产品叫机长，界面却像备忘录。
2. **信息层级平**：任务行信息密但重点弱，"下一班飞机什么时候起飞"这个最重要的信息被埋在列表里。
3. **设置心智重**：飞行外观设置是一排下拉框，用户要理解"尾焰=飘带"的抽象映射，试错成本高。

### 5.2 新概念：「航站楼」（Terminal）

把主界面从"任务列表"重构为**机场航班信息板**——用户每天打开就像走进自己的航站楼：

| 概念映射 | UI 表现 |
|---|---|
| 任务 = 航班 | 每行是一班航班：目的地（任务名）、起飞时间、登机口状态 |
| 状态 = 航班动态 | `即将登机`（5分钟内）/ `准点` / `延误`（被智能暂停推迟）/ `已取消`（禁用）——翻牌式状态切换动画 |
| 下一班 = Hero 大卡片 | 顶部巨幅展示下一班：倒计时 + 飞机沿跑道滑跑起飞的实时动画 |
| 分组 = 航站楼屏显 | 近期提醒 / 特殊日期 / 已停用 分区如机场航显屏 |
| 飞行预览 = 实时塔台 | 设置外观时右侧小窗实时预览飞行效果，改即所见，不再靠想象 |

设计系统升级：

- **视觉**：深色优先的"夜间机场"氛围——跑道灯带渐变、琥珀色（候机厅灯光）+ 青蓝（夜空）双色 accent、玻璃拟态卡片；浅色版是"清晨机场"
- **动效**：翻牌时钟（split-flap）数字切换、飞机起飞抛物线微动画、卡片 staggered 入场
- **效率**：`⌘K` 命令面板（搜索任务/快速起飞/新建/设置一站式）；任务行 hover 显快捷操作
- **陪伴感**：空状态/加载态都有机长插画出镜；文案从"系统腔"改为"机长腔"

> 高保真交互原型见 [`ui-concept.html`](./ui-concept.html)（浏览器打开可体验翻牌动画与起飞 Hero）。

### 5.3 设计原则（写入团队共识）

1. **航空隐喻贯穿到底**：所有文案、状态、空页面都用航空语言（"航班""登机""延误""返航"）
2. **改即所见**：任何外观/声音设置必须实时预览，消灭下拉框猜谜
3. **三秒原则**：打开主窗口 3 秒内必须知道"下一班飞机几点飞"
4. **温和打断**：所有 UI 动效节奏 ≤ 300ms，飞行本身是唯一的"重动效"

## 七、风险与对策

| 风险 | 对策 |
|---|---|
| 智能时机检测跨平台差异大（macOS 权限、Win API） | 分级降级：检测不到就用保守策略（全屏即推迟），宁缺勿滥 |
| 常驻机长增加内存占用（当前 <50MB 是卖点） | 动画帧预算硬上限；mini 窗空闲时降到 1fps 呼吸态 |
| MCP/AI 功能引入安全面（外部触发飞行） | 沿用 `run_script` 白名单思路：MCP 工具只暴露创建/触发，不暴露执行 |
| 皮肤市场 UGC 合规（侵权 IP） | 1.0 只做本地导入导出 + 用户自担分发；官方市场缓行 |
| Pro 收费引发开源社区反弹 | 核心功能承诺永免费并写入 README；Pro 只碰云与 AI |

## 八、一句话路线图

> **v0.9 聪明**（在对的时间出现）→ **v1.0 陪伴**（常驻机长 + 同步 + 皮肤）→ **v1.1 连接**（日历 + MCP + AI）→ **v1.2 商业**（Pro 订阅 + 小信号）

先做留存，再做热爱，最后做收入。
