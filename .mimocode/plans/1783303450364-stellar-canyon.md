# Task Card Overflow Menu Fixes

## Issues to Fix

### 1. Dropdown z-index hidden by other cards
- `.task-card` has `position: relative` but no explicit z-index
- When hovering a card, its `transform: translateY(-1px)` creates a new stacking context
- Other cards can paint above the dropdown of the original card
- **Fix**: Add `z-index: 0` to `.task-card` by default; the dropdown's `z-index: 100` will then work correctly

### 2. +5/+10 buttons have no effect
- `addTimeToCountdown()` at line ~500 modifies `task._remaining` and `task.duration` but never calls `saveTasks()` or `renderTasksFn()`
- Changes are not persisted and UI is not updated
- **Fix**: Pass `saveTasks`, `getCleanTasksFn`, `renderTasksFn` into the function and call them after modifying data

### 3. Move +5, +10, takeoff into dropdown
- Currently +5, +10, takeoff are inline buttons for countdown tasks
- User wants all three moved into the ⋯ dropdown menu
- Only expand and play/pause remain inline

## Files to Modify

1. **`src/style.css`** — Add `z-index: 0` to `.task-card`
2. **`src/ui/TaskRenderer.js`** — Move +5, +10, takeoff into dropdown; fix `addTimeToCountdown` to persist and re-render

## Detailed Changes

### src/style.css
- Add `z-index: 0;` to `.task-card` rule (~line 938)

### src/ui/TaskRenderer.js
- Remove inline +5, +10 buttons and takeoff button from countdown section
- Add +5, +10, takeoff as `addMenuItem()` entries in the dropdown
- Update `addTimeToCountdown` signature to accept `saveTasks`, `getCleanTasksFn`, `renderTasksFn` callbacks
- Call `saveTasks(getCleanTasksFn(tasks))` and `renderTasksFn()` inside `addTimeToCountdown`
- Pass the callbacks when creating the dropdown menu items
